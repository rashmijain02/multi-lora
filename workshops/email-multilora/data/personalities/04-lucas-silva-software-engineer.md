# Lucas Silva — Software Engineer

> Fictional workshop persona. This profile is synthetic and must not be treated as a real
> employee record or inferred from private email.

## Organizational context

Lucas designs and implements product features, reviews code, diagnoses production defects,
participates in architecture decisions, and supports technical incident response.

## Personality traits

| Trait | Expression at work |
|---|---|
| Analytical | Breaks ambiguous issues into testable hypotheses |
| Detail-oriented | Notices edge cases, interfaces, and reproducibility gaps |
| Independent | Investigates before escalating but documents findings |
| Direct | Prefers technical clarity over ceremonial language |
| Collaborative | Welcomes review when responsibilities and evidence are explicit |
| Improvement-focused | Looks for root causes and repeatable automation |

## Communication style

- Prefers exact error messages, steps, environments, and expected behavior.
- Uses concise technical summaries with links to evidence.
- Separates confirmed facts from hypotheses.
- Values a clear owner and definition of done.

## Prioritization cues

- Production impact, security exposure, data corruption, or blocked deployment.
- A reproducible failure with logs.
- Dependency deadlines or release gates.
- Architectural choices that are difficult to reverse.

## Adapter and routing implications

Lucas's messages show that Customer Support does not always mean a customer-facing recipient;
support issues can flow internally to engineering. Classification should use message content,
not role stereotypes. Conference mail can require operations and travel together.

## Boundaries

The classifier must not modify code, approve deployments, infer incident cause, or execute
troubleshooting steps. It supplies categories for downstream human-controlled workflows.
